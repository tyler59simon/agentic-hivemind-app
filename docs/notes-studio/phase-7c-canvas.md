# NS-7C: canvas boards

Read [README.md](README.md) first. Canvas boards use the open JSON Canvas format (`.canvas`, as Obsidian writes it), so boards move between Hivemind and Obsidian.

## Changes from the code survey before NS-7C

Claude surveyed main at `6007ce8` on 2026-11-22. Where the text below says otherwise, these win.

- **The index already reads canvases.** NS-4A's `notes_index/extract.rs` (`canvas()`) indexes text node content, headings, tags and links, and `PageKind` includes `canvas`. This phase adds no index work beyond file references if `canvas()` misses them.
- **A `.canvas` file opens as plain JSON text today.** The board is a new editor loaded lazily in `FileTab.tsx`, as `HmdocEditor` is for `.hmdoc` (NS-3C), with Board and Source modes. It edits the page through the document session (`src/documents/store.ts`), so saving, drafts, history, the hash precondition and the changed-on-disk banner work as for every page. The doc's "keep mine, keep theirs, save both" is that existing conflict flow, not a new one.
- **Pictures and PDFs on file nodes** load through the notebook asset grant (`asset_base`, the `hmfile` scheme), as NS-3D embeds do in `src/features/hmdoc/blocks/embedViews.ts`.
- **Memory note cards** reuse the NS-3D memory note card (`noteCard` in `embedViews.ts`) where it fits.
- **Notebook tree rows are not draggable today.** Dragging a page onto a board needs the tree rows to set a drag payload (notebook id and path) that only the board accepts; the tree's own behaviour must not change.
- **New canvas** is a notebook and folder menu action next to New page, making `Untitled.canvas` with `{"nodes":[],"edges":[]}`.
- **Rendering:** plain DOM and CSS transforms unless the spike shows `@xyflow/react` is clearly better; record the decision and the reason in section 4. A new dependency is pinned at an exact version.

## 1. What the user sees

- **New canvas** in a folder notebook. An infinite board with pan and zoom; nodes: **text** (Markdown, edited in place), **file** (a page, an image or a PDF from the notebook, rendered as a card or the image), **link** (a URL shown as a card with its title, never an iframe), **group** (a labelled box). Edges between node sides, with labels and arrowheads. Colours from the JSON Canvas preset set, mapped to theme tokens.
- Drag pages from the notebook tree onto the board; double-click a file node to open it in a tab.
- Memory notes can be placed as file-like cards (stored as a link node with a `hivemind:mem:` URL in a Hivemind field, so Obsidian shows a plain link).

## 2. Design

- `src/features/canvas/{model.ts, CanvasBoard.tsx, nodes/*}`: the model reads JSON Canvas 1.0, keeps unknown node and edge fields and unknown top-level keys on save, and writes stable key order.
- Rendering with plain DOM and CSS transforms (no new dependency) unless the spike in this phase shows that `@xyflow/react` (MIT) is clearly better; the decision is recorded here.
- Text extraction for the index: text node content and file references (NS-4A extractor).
- Conflicts: keep mine, keep theirs, save both.

## 3. Tests and exit

vitest: model round trip with unknown fields, edge validation, colour mapping. Exit: an Obsidian-made canvas opens and saves without losing any field; Memory regression pass.

- **Found and fixed in this pass:** that Source view was empty. `CodeEditor` returned its host element alone without the power bar and inside a fragment with it, so when a canvas switched from Board to Source after the first render, React replaced the host and the CodeMirror view stayed in the old one. The host now keeps its place (`CodeEditor.tsx`, test `CodeEditor.host.test.tsx`, which fails without the fix).
- Not checked in the app: the conflict banner (Keep mine, Keep theirs, Save both), Memory note cards, group moves and 500-card performance; these are covered by `FileTab.canvas.test.tsx` and `CanvasBoard.test.tsx` only.

**Rendering decision: plain DOM and CSS transforms; no new dependency.** `@xyflow/react` was not spiked. The phase needs pan, zoom, select, move, resize, join and label, which is small. The JSON Canvas file has to stay the model either way (unknown fields kept, a fixed key order), so a library's own node and edge objects would have been converted both ways. The 500-card requirement is met by moving one element: the board is a `translate` and `scale` on a single world element, cards and edges are memoized components, and a gesture hands out new objects only for the cards it changed. The cost is that hit testing, handles and the join line are written here and were only driven in jsdom (see Known limits).

**Webview** (`src/features/canvas/`)
- `model.ts`: the JSON Canvas 1.0 model over plain objects. `parseCanvas` keeps every field of every node and edge (typed for the known ones, as read for the rest), cards of a type it does not draw, and the top-level keys other than `nodes` and `edges`. It refuses, with a reason, what the board could not hold without losing data: invalid JSON, a top level that is not an object, lists that are not lists, a card without an id, a type or four numbers, a text, file, link or group field of the wrong type, duplicate card or edge ids, an edge without an id or ends, a side that is not `top`, `right`, `bottom` or `left`, an end that is not `none` or `arrow`. `writeCanvas` writes tab-indented JSON with one card or edge per line as Obsidian does, known keys in one fixed order (cards: `id`, `type`, the content keys, `x`, `y`, `width`, `height`, `color`; edges: `id`, `fromNode`, `fromSide`, `fromEnd`, `toNode`, `toSide`, `toEnd`, `color`, `label`), unknown keys after them in the order they were read, and no trailing newline. Also here: `colourOf`, the edge curve and arrowhead geometry, `fitView`, `zoomAt` and the changes (`addNode`, `moveNodes`, `resizedBox`, `setNode`, `setEdge`, `removeItems`, `connectProblem`, `addEdge`, `inside`, `reuse`).
- `CanvasEditor.tsx` (the lazy chunk, about 21 KB): parses the document session's text, hands the whole file back through `onChange` after each gesture, and keeps undo and redo. `reuse` gives a card or edge that did not change the same object as before, so a commit draws only what changed.
- `CanvasBoard.tsx`: the viewport and every gesture. Pan (drag empty space, wheel), zoom (Ctrl and wheel about the pointer, buttons, Fit; Fit also runs once when a board opens), select (click, Shift to add, Ctrl+A), move (a group takes the cards wholly inside it), resize (four corners, never below 60 by 40), join (drag from a side handle to another card; the nearest side of that card is the end), edit text in place (double-click, Ctrl+Enter or leaving the card writes, Escape gives up), edit a group label, a link address and an edge label (double-click, Enter or Escape), double-click empty space to add a text card, Delete, Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z, and colour swatches for the selection. A gesture shows a preview and calls `onCommit` once, when it ends.
- `nodes/NodeView.tsx`: the cards. Text is `PageView` (the Reading view: no raw HTML, and `[[links]]` follow as in a page). File is a picture through the notebook's `hmfile` grant, or a card with the page title, path and `subpath` (a PDF is a card, not a page). Link is the host and address with an "Open in browser" button. Group is a dashed box with a label. A link whose address starts with `hivemind:mem:` is a Memory note card drawn from `read` with `cardLines` from the NS-3D card. Any other type is a named card that is kept as it is.
- `Edges.tsx`: one SVG under the cards and an HTML label at each edge's middle. `FilePicker.tsx`: pick a file of the notebook. `treeDrop.ts`: see Deviations.
- `FileTab.tsx`: a `.canvas` file has Board, Source and History. The Board tab loads `CanvasEditor`. `canvasProblem` decides before anything is drawn, and a file the board cannot hold switches the tab to Source with "This canvas cannot be shown as a board: <reason>. It is open as source, and nothing was written." The conflict banner is Keep mine, Keep theirs and Save both, and Save both writes `Name (my edits).canvas`.
- `actions.ts`: `newCanvas` (`Untitled.canvas` holding `{"nodes":[],"edges":[]}`, free name, opens as a board); `openPage` opens a canvas as a board. `NotebookTree.tsx`: New canvas in the notebook menu, New canvas here on a section's menu, an icon of its own, and the drop hook. `workspace/store.ts`: mode `board`. `lib/notebooks.ts`: `isCanvas`. `documents/store.ts`: a draft for a canvas is never merged line by line (`.hmdoc` already was). `App.css`: `.canvas-*`.

**Rust**
- `notebooks/mod.rs`: `canvas` joins `TEXT_EXT`, so the tree lists a canvas as a text file, not as a file for the system app. NS-4A's `canvas()` already indexes card text, group labels, link addresses, edge labels and file references, so there is no other Rust change.

**Deviations**
- A page dragged from the tree uses pointer events, not an HTML5 drag payload. The tree already moves rows with pointer events (its own comment: HTML5 drag and drop is unreliable in WebView2 with Tauri's own drop handling), so a row let go outside the tree is now offered to `dropOnBoard` (`treeDrop.ts`) with `{ notebook, path }`. Only a mounted board registers to take it. It takes it only for its own notebook and only when it can be edited. A section is never offered, and a drop over the tree is the tree's own move and never reaches a board. The tree's rows and their behaviour are otherwise unchanged.
- A Memory note on a board is a link card with `url: "hivemind:mem:<ref>"` and no other field (the survey says "in a Hivemind field"; Obsidian shows the address as a plain link either way). The title and first lines are read when the card is drawn, and nothing about the note is copied into the file. The Memory note button adds one, through NS-3D's note picker.
- The JSON Canvas preset `"5"` (cyan) is drawn with the rich page palette's blue, since the palette has no cyan and a new token would change the 16 `--pal-*` tokens that `theme.test.ts` counts. `"1"` to `"4"` and `"6"` are red, orange, yellow, green and purple. A hex colour is drawn as given; only `#rgb`, `#rgba`, `#rrggbb` and `#rrggbbaa` reach a style.
- Undo and redo are kept by the board's editor, not by the document session, which has none. Each commit stores the text before it (up to 200) and an undo hands that text to the session, so undoing everything returns the page to clean. A change that did not come from the board (a reload, a merge, the Source tab, another pane) empties both lists.
- An edge that names a card that is not there is kept in the file and not drawn, with a note on the board; it is not a reason to refuse the file. A blank file is an empty board and stays unwritten until something is added.
- Deleting a card deletes its edges. Dragging a group moves the cards wholly inside it (by their boxes at the start of the drag). A group is grabbed by its label, so its empty inside pans the board.
- Arrowheads follow the file (`toEnd` is an arrow unless it says otherwise, `fromEnd` is none) and are kept, but the board has no control to change them.

**Known limits**
- Not run in the app. The gestures were driven in jsdom by dispatching pointer, wheel and key events, which checks the logic and the commit counts, not the feel in WebView2 (hover handles, cursor shapes, the CSS layout, dragging a tree row onto a board with a real mouse, frame time with 500 cards). The 500-card tests count how often cards draw; they do not time a frame.
- Obsidian's own key order and layout were written from memory, not checked against a current Obsidian. The first save of a file that is not in this layout rewrites its whitespace and reorders keys; the data is the same. A canvas nothing was changed in is never written.
- A file card shows the page's title and path, not its text; a PDF is a card, not its first page. A file card names a path from the notebook's root, so a canvas opened from outside a notebook has no pictures and no file picker.
- No grid or snapping, rectangle select, copy and paste, reconnecting an edge, a new card from an edge dropped on empty space, or minimap. The view (pan and zoom) is not saved; a board opens fitted.
- A text card with more text than fits cannot be scrolled with the wheel, which pans the board over a card as anywhere else; enlarge the card to read it.
- A canvas in a Living Memory notebook is not possible (Living Memory keeps Markdown pages), so New canvas is not offered there.
